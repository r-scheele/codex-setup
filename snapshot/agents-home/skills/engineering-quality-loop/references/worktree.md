# Select the task worktree before writing

1. Inspect the repository root, branch, HEAD, existing worktrees, and working changes using read-only Git commands. Record the task's intended starting commit and any explicitly requested uncommitted input. Preserve unrelated changes. Do not stash, reset, commit, or transfer unrelated dirty files to make setup convenient.
2. Ask the user to choose one option: continue in the exact worktree from the referenced previous task, or create a fresh worktree. If the current request already makes that choice, proceed without asking again. Do not infer that a similarly named worktree belongs to the task.
3. For a previous-task worktree, verify its absolute path, branch, base, current diff, and that it contains the intended task state before accepting it. For a fresh worktree, fetch the selected base when required by project policy, then create a new task-specific worktree and unused neutral branch. Do not create a second chat or fork merely to obtain a worktree.
4. Work only through the selected worktree's absolute path. The current chat may remain attached to another checkout; use explicit working directories for commands, edits, tests, review panels, and Codiff. Non-Git folders block this workflow; do not initialize a repository or create an initial commit automatically.
5. Verify `git rev-parse --show-toplevel`, `git branch --show-current`, and `git worktree list --porcelain` agree on the selected absolute path and branch. Record the worktree path, branch, and base in the task evidence. Check again after any resume or unexpected cwd/branch change. Subagents use this exact root for commands and edits; they do not create additional worktrees or branches.

Only this task's selected worktree is used for implementation and its file/review panels. This does not remove other chats/worktrees from the global sidebar, erase prior conversation references, or change filesystem permissions. Required installed skills/tools and task evidence can remain outside the source root. Do not claim a hard filesystem sandbox.

Official app behavior checked 2026-09-10: [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees). App-managed worktrees remain supported, but chat attachment is not required by this workflow.
